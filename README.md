# 贪吃蛇 · Canvas

一份 **纯静态** 的 Canvas 贪吃蛇。前端不依赖任何框架、构建工具或 Tauri API ——
既可以用浏览器直接打开（`file://` 也行），也可以套进 Tauri 壳里当桌面程序跑。

## 在线版（什么都不用装）

纯前端那份已经部署好了：**GitHub 仓库 → Netlify** 自动构建，直接打开就能玩：

**<https://renjisnake.netlify.app/>**

只发布 `index.html` + `assets/`，也就是 Tauri 壳之外的那份纯静态页面 —— 和仓库里是同一份代码。

因为它是 `https://` 页面，浏览器会把对 `http://192.168.x.x` 的请求当**混合内容**拦掉，
所以**在线版上联机只有「连接码」这一条路**（走 WebRTC 直连，不需要任何服务器）。
想用「直连 / 局域网搜房」请用**桌面版**，或者把页面用 `file://`、本地 http 打开。

更新线上那份有两种办法：

1. **推 GitHub**（推荐）：Netlify 连着 GitHub 仓库，push 上去它自己重建 —— 什么都不用做。
2. **手动拖**：`npm run pack:netlify` 会生成 `release/netlify/`（目录）和
   `release/netlify-0.3.0.zip`，把其中任意一个拖到 Netlify 的 Deploys 页面即可，
   不用碰 GitHub。包里只有 `index.html` + `assets/`。

## 玩法

| 模式 | 说明 |
|---|---|
| 单人 | 15×15 场地 |
| 本地双人 · 合作 | 30×15，队友出局后场上会掉复活道具，活着的人吃到就能救回来 |
| 本地双人 · 竞争 | 30×15，炮塔会把对方也算进目标，先出局的一方输 |
| 联机对战 | WebRTC 直连，最多 **6 人**同局 + 观战席；一条连接一个座位，程序版本不一致会直接拒绝连接 |

键位：P1 方向键 + `/` 建塔，P2 WASD + `Q` 建塔，
`P` 暂停，`C` 房间设置，`T` 聊天，`Esc` 回模式选择。屏幕上也有方向键、建塔、设置和聊天按钮。

## 手机

手机上直接用屏幕上的方向键操作（触摸设备下会放大到 66px，整行功能键 48px）：

- **棋盘自适应**：窄屏时画布等比缩到屏宽（`max-width` + 高度 `auto`），30×15 的场地也不会横向溢出；
  在棋盘上滑动不会被当成滚动，双击也不会缩放页面（`touch-action`）。
- **本地双人**：底部会多出**第二套方向键**（只有本地双人才出现），两个人各按各的；
  联机客机只有自己那一个。
- **一屏放得下**：开局后长篇帮助会自动收起（`body.playing`），打完回菜单再出现；
  刘海屏用了 `env(safe-area-inset-bottom)`。
- 输入框在手机上字号 ≥16px —— 否则 iOS 一聚焦就把整页放大。

手机上最快的试法：浏览器打开 <https://renjisnake.netlify.app/>（单人 / 本地双人 / 连接码联机都能玩）。
要跟电脑上的 Tauri 房主联机，见下面「手机连电脑一直打洞超时？」那一节。

## 怎么跑

### 1. 浏览器（零依赖）

不想下载就用上面的[在线版](#在线版什么都不用装)。本地双击 `index.html` 也能玩；
想联机的话建议起个 http 服务 —— 本地 http 页面既能用「连接码」，也能「直连」进房间
（`file://` 下 WebRTC 没验证过）：

```bash
python -m http.server 8080
```

### 2. 桌面程序（Tauri 2）

需要 Rust 工具链 + Node；Windows 上还需要 WebView2 运行时（Win10/11 一般自带）。

```bash
npm install              # 只装 Tauri CLI
npm run fetch:easytier   # 下载跨网用的 EasyTier（不联机跨网可以不装）
npm run dev              # 开发模式
npm run build:exe        # 只编译出 exe（快，约 1.5 分钟）
npm run build            # 完整发布包：exe + EasyTier + 便携 zip
```

前端文件**始终留在仓库根目录**，`dist/` 是构建时生成的、不入库。

产物固定在这个路径（`scripts/pack-exe.mjs` 会把 exe 拷过来，
不管机器上的 `CARGO_TARGET_DIR` 指到哪）：

```
src-tauri/target/release/snake-army.exe
```

中间产物仍然留在 `CARGO_TARGET_DIR`（本机是 `C:\rust-targets`），
那里是全机器共享的缓存，项目里只放最终那一个 exe。
Tauri 壳里没有任何业务逻辑，只负责给一个原生窗口和 WebView2。

### 3. 局域网主机（可选）

```bash
python lan-host.py 8080
```

会打印局域网地址，同一个 Wi-Fi 下打开就能拿到游戏。
背景：浏览器不能监听端口、不能收广播，也没有 mDNS 浏览 API，所以「自动搜索房间」
必须有一台机器在监听 —— 这个脚本就是那一台。页面侧的一键进房 UI 还没接。

## 联机

### 几个人一局 / 观战

一条连接 = 一个**座位**。座位 0 是主机自己，1..5 是客机，负数座位是**观战席**。

- 最多 **6 人**同局（`MAX_PLAYERS`）。主机可以一位一位地加人：连接码模式里接上一位之后，
  按钮会变成「再让一个人进来」；局域网开房则是一次把各个座位的 offer 都挂上去，
  谁先点「进入」谁先坐。
- 每个客机各自驱动自己那条蛇：主机按座位把按键喂给对应的蛇，客机只发按键、收快照。
  快照是**一人一份**的 —— 同一帧内容一样，只有 `you` 不同，客机据此知道自己是谁，
  状态条上写着「我是客机（座位 N）」。
- **玩家席满了还能进**：多出来的连接坐观战席，只收快照、不发任何操作；
  状态条写「观战中 · 只能看，不能操作」，请求暂停 / 重开的按钮直接隐藏。
- 打到一半有人进来会**当场补一条蛇**（`addPlayerAt`），不用重开一局。
- 屏幕上的**建塔按钮在联机时只显示你自己那条蛇** —— 座位 3 就写「我（P3）」，
  并按你自己的身长/货币变灰；观战席一个按钮都不给。本地双人则是 P1/P2 一人一个。
- 有人断线只让那个座位空出来，别人不受影响；那条没人开的蛇留在场上自己撞墙为止。

### 桌面版：局域网自动搜房（推荐）

桌面版里 Rust 侧内嵌了信令服务 + UDP 广播探测，同一个 Wi-Fi 下：

1. 主机：「联机对战」→ 填房间名 / 场地宽高 / **人数上限（2-6）** →「**开个房间**」
2. 客机：「联机对战」→「**搜索房间**」→ 列表里点「进入」（玩家席满了就点「观战」）

不用交换任何连接码，也不用跑 `lan-host.py`。

### 浏览器版：靠「直连」进房

浏览器**开不了房**（网页不能监听端口），但**可以进别人的房间**：让对方用桌面版开房，
把界面显示出来的地址（`IP:端口`）发给你，在「直连」里粘进去就能进。
这条路上浏览器只做它本来就会的事：fetch 对方地址要房间列表和 offer、RTCPeerConnection 建连，
CORS 在内嵌服务上已经开了 `*`。

**注意**：页面如果是用 `https://` 打开的，浏览器会拦掉 `http://` 的地址
（混合内容），进房会失败；用 `file://` 打开或本地 http 服务则没问题。

### 浏览器版：手动交换连接码

纯浏览器没有原生侧那半边能力 —— 网页不能监听端口、不能收 UDP 广播、也没有 mDNS 浏览 API，
所以「搜索房间」那一块**在浏览器里会整个隐藏**，自动退回手动连接码。
前端核心逻辑一行都没为桌面版改过，同一份 `index.html` 两边都跑。

### 端口

| 用途 | 端口 |
|---|---|
| 信令 HTTP | 优先 **47812**，被占（例如同机开了第二个实例）则退回系统随机分配 |
| UDP 探测 | 固定 **47811**；被占则本机不做应答，其它功能照常 |

### 信令接口

桌面版的 `src-tauri/src/lan.rs` 和 `lan-host.py` 实现的是**同一套**接口
（所以前端只有一条代码路径：给它一个 base 地址就行）。

| 接口 | 作用 |
|---|---|
| `GET /api/ping` | 探活 |
| `GET /api/rooms` | 房间列表，含 `players` / `maxPlayers` / `spectators` / `freeSeats` / `freeSpectatorSeats` / `taken` |
| `POST /api/room` | 建房：`{name, desc, player, cols, rows, maxPlayers}`（不再需要 offer） |
| `POST /api/offer` | 房主挂某个座位的 offer：`{id, seat, offer}` |
| `GET /api/offer?id=` | 来客取座位 → `{seat, offer, name}`；先玩家席、再观战席，都没有返回 409 |
| `POST /api/answer` | 来客递答应码：`{id, seat, answer}`；同一座位重复递返回 409 |
| `GET /api/answers?id=&players=` | 房主轮询 → `{answers:[{seat,answer}]}`；故意「读不消费」，由房主按座位去重 |
| `POST /api/close` | 关房 |

座位号是这套接口的核心：房间不再只有一对 offer/answer，而是**一张座位表**。

### 跨网（EasyTier 虚拟局域网）

联机面板上选「**跨网**」：

1. 先准备二进制：`npm run fetch:easytier`
   （走 ghfast.top 镜像下载，因为不少机器把 github.com 整个 hosts 掉了）
2. 两边填**一样的**网络名和密码 →「启动虚拟局域网」
3. 虚拟网起来之后，面板上会出现「搜索房间 / 开个房间」—— 和同一个 Wi-Fi 时**用法完全一样**

原理：EasyTier 会把你们接进同一张虚拟局域网，而它有一个
`--enable-udp-broadcast-relay`（仅 Windows）会把本机 UDP 广播转发给对端节点，
官方说明就是「帮助局域网游戏发现房间」—— 正好让上面那套 UDP 搜房跨网生效。
所以跨网不是另写一套联机，而是**把跨网变成局域网**。

**两个前提**：

- **需要管理员权限**：EasyTier 建虚拟网卡绕不开 TUN/wintun。没管理员时程序会明确提示，
  而不是让你干等；EasyTier 自己的日志在面板里也能看到。
- **需要一个会合点**：官方的 `public.easytier.cn` 已经 NXDOMAIN 了。
  可以填社区共享节点的 IP（`tcp://IP:11010`），或者自己起一台 ——
  所谓公共共享节点，就是「网络名密码相同的普通 EasyTier 节点」，放在有公网 IP 的机器上即可。

**不装 EasyTier 的退路**：面板上的「连接码」类型仍然可用；
配合自建 coturn / 商业 TURN（填进「ICE 服务器」框）一样能跨网。

### 联机类型对照

| 类型 | 需要什么 | 怎么用 |
|---|---|---|
| 局域网 | 同一个 Wi-Fi | 一边「开个房间」，另一边「搜索房间」→ 加入 |
| 跨网 | 管理员权限 + 会合点 | 两边填一样的网络名密码 → 起来后同局域网 |
| 连接码 | 无 | 手动把码发给对方 |

浏览器版只有「连接码」一种，类型选择器整个隐藏 —— 那两种都要原生侧才做得到。

### 手机连电脑一直「打洞超时」？

同一个 Wi-Fi 下本来只靠本地候选就能连通，但下面三件事会让它连不上，按可能性从高到低：

1. **电脑防火墙没放行 UDP**（最常见）。桌面版真正收发媒体的是 **WebView2 进程**，
   不是主程序本身。去「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」，
   把 `snake-army.exe` **和 `msedgewebview2.exe`** 的「专用」「公用」都勾上；
   再确认这个 Wi-Fi 在网络设置里是「专用网络」而不是「公用网络」。
2. **浏览器把本地候选写成 mDNS 名字**（`xxxx.local`）。实测电脑这边给出的本地候选就是
   `1d93f739-….local 62364 typ host` 这种（见下面的实测），手机端经常解析不了；
   场上剩下的公网候选又得靠路由器的 NAT 回环（hairpin），家用路由器大多不支持 ——
   于是 ICE 一个能用的候选对都没有，只能等到超时。
   现在的做法：**从房间地址里取主机的局域网 IP**（`http://192.168.x.x:端口`），
   用 `netPatchIp` 把 mDNS 候选补成真地址；连接码模式则把主机的 IP 直接写进码里，
   对方不用手输。进入房间后状态栏会写「已按主机的局域网地址 192.168.x.x 补了 N 条候选」——
   **补上了还超时，基本就是第 1 条（防火墙）或者第 3 条。**
3. **手机和电脑其实不在同一个局域网**：手机流量、访客 Wi-Fi 的 AP 隔离、公司网都算。
   确认手机连的是同一个路由器，并且路由器没开「AP 隔离 / 客户端隔离」。

跨网（两边不在同一个网络）本来就打不通：那需要 TURN 中继，或者用「跨网」里的 EasyTier
把两边接进同一张虚拟局域网。

实测（本机 headless Edge 出的 offer，和桌面版同引擎）：

```
总候选 9 | mDNS 2 | 真 IP 6 | 计数器 {"host":2,"mdns":2,"srflx":7,"relay":0}
83450558 1 udp 2113937151 1d93f739-a29c-4bbc-acda-23718c9eeb4a.local 62364 typ host
1339568902 1 udp 2113939711 2d269b7b-9ff6-4f03-aa8a-5a24ae2022d1.local 62365 typ host
932239822 1 udp 1677729535 122.96.37.181 22309 typ srflx raddr 0.0.0.0 rport 0
```

两个本地候选都是 `.local`（mDNS），一个真地址都没有 —— 这正是手机解析不了的原因。

### 关卡修改器（一个页面，本地和联机开房共用）

游戏里按 `C`（或点操作区的「⚙ 设置」）打开；开始界面和联机面板上也有入口。
**本地单人 / 本地双人 / 联机开房**改关卡都走这一个页面（`assets/level.js`）。

页面由一张表生成（`LEVEL_FIELDS`）—— 加一个可调参数只要在那里加一行，
输入框的 id、范围、生效方式、快照同步、短码打包全都跟着走。

| 组 | 项 | 生效方式 |
|---|---|---|
| 场地与玩法 | 场地宽/高（调试用）、合作/竞争、人数上限 | 立即（场地变小会重开一局）/ 人数开房时定 |
| 蛇 | 初始身长、每节血量、**每步间隔**（50 ~ 1200ms） | 身长血量下一局；**步长立即** |
| 场上刷什么 | 同屏苹果、敌人开关、敌人上限、**敌人速度（%）**、敌人补位、道具总开关、道具刷新总倍率（%）、加速时长、复活道具 | 全部立即 |
| 每种道具 | **加速 / 拓宽各自**的生成开关、刷新间隔（毫秒）、**同屏上限（1~6 个）** | 全部立即 |
| 炮塔 | 建塔耗身长、建塔耗币、塔上限 | 全部立即 |
| 房间信息 | 房间名、房间描述 | 立即，跟着快照发给客机 |

场地范围 **10×8 ~ 200×150**（宽 × 高，格）。有了摄像机，大地图不是「缩小到看不清」，
而是「格子照样 20px、镜头跟着你走」；信令服务端夹的范围和这里一致。

「敌人速度」是**倍率**（100 = 原速）而不是绝对值 —— 紫/红/蓝本来快慢不同，改倍率这个差异还留着；
「道具刷新」是刷新间隔的百分比（25 = 4 倍频），**每种道具自己的间隔再乘这个倍率**。

每种道具可以单独设：**要不要生成**、**隔多久刷一个**、**同屏最多几个**。
默认值和加这个功能之前完全一样（加速 10 秒 / 拓宽 12 秒、各 1 个）。
同屏允许多个之后，道具状态从「每种一个槽」变成「每种一个列表」——
绘制、拾取、快照、短码都跟着走，联机时客机也照收。

客机打开同一个面板只能看（输入框和按钮全是禁用的），但可以**下载**或生成**短码**把自己看到的关卡带走。
配置走的是同一个结构体 `levelCfg`（state.js），快照里整个带过去，所以加一项只要改这一处。

### 关卡预设

页面顶部一个下拉框，选中即套用。预设**只覆盖「关卡」那一半**，房间名 / 描述 / 人数上限不动。

| 预设 | 内容 |
|---|---|
| 经典 | 默认那套：15×15 慢慢吃 |
| 大乱斗 | 80×40、380ms、8 个苹果、12 条敌人、8 座塔 |
| 生存 | 40×30、每节 3 血、苹果只有 2 个、敌人不断补、塔上限 2 |
| 空场练习 | 30×20、关掉敌人、300ms，专心练手感 |
| 巨幕 | 200×150 大地图，镜头跟着你走 |
| **高铁大陆** | **200×150 极速：玩家 100ms、敌人 5 倍速、道具刷新 25%（4 倍频）、12 个苹果、12 条敌人** |
| 闪电战 | 180ms 一步、1 血，撞一下就出局 |

自己改完可以**存为预设**（存在 localStorage，同名覆盖）、**下载成 .json**、**加载文件**（或短码）。
导进来的内容会过一遍白名单 + 范围夹取：手改过的文件设不了 99999 格的场地、1ms 的步长。

### 分享短码

```
贪吃蛇·高铁大陆·200x150·68Q7#SNK#L1#H#景天五天玄天荒玄玄盈天辰辰曰地洪天调天余玄地辰辰璧改恭璧临凤缘男良璧惟食天
└──────── 给人看的 ────────┘ └──────────── 给程序看的 ────────────┘
```

- 前面那段（名字 / 尺寸 / **指纹**）是给人的：一眼知道这是什么关卡；指纹是内容的 CRC 取 4 位，
  抄漏一段或被聊天软件截断时，导入会提示「⚠ 指纹对不上」。删掉前缀也能用，老码（没有前缀）也认。
- 两种载荷：`A` = base64url（短），`H` = **汉字** —— 每个字节对应《千字文》里的一个字
  （256 个互不相同，正好拿它当字母表）。页面上「编码：紧凑 / 汉字」可切换。
- 关卡是**打包成二进制**再编码的（不是 JSON）：步长按 10ms、补位按 500ms、加速按 1s 缩放，
  开关塞标志位，名字/描述用 UTF-8。一个完整关卡 40 字节左右。
- 聊天里带短码的消息旁边会多一个「导入这个关卡」按钮，点一下直接套用并打开修改器。

聊天：按 `T` 或点「💬」，底部抽屉 —— 回车发送、`Esc` 收起，关着时按钮上显示未读数。
主机转发：客机 → 主机 → 其他所有人（说话的人自己不会再收一遍），观战席也能说话；
单机时消息只留在自己屏幕上。消息一律用 `textContent` 渲染，不会被当成 HTML，
单条上限 200 字、本地只留最近 100 条。焦点在输入框里时游戏快捷键全部让路 ——
否则聊天里打 `w`/`a`/`s`/`d`/`p` 会顺手把蛇拐弯、把局暂停。

## 验证页面（两个工具；重要：别按进程名杀浏览器）

改完页面要跑一遍真实浏览器验证时：

```bash
npm run probe      # 一键：同步 dist/ -> 起静态服务 -> 无头 Edge 跑探针 -> 打报告
npm run serve      # 只想自己打开看时：静态服务（默认 9211，可传端口）
```

`npm run probe`（`scripts/probe-web.mjs`）做两件事，缺一个、错一个都会红着退出：

* 把 `assets/` 与主脚本里**所有**顶层声明的名字列出来，在真实页面上逐个 `typeof` 一遍
  —— 拆文件最容易犯的错就是「函数搬过去了但没人定义」或「忘了加 `<script src>`」
* 真的开局跑几百帧：走位、建塔、拓宽、敌人推进、快照往返、暂停、双人、重开

> 这台机器上 `--dump-dom` / `--screenshot` 会**静默返回空**（Edge 155 起这两个一次性开关
> 就不出声了，任何页面、任何 headless 模式都一样）。要截图/量尺寸请用 `scripts/shot.mjs`
> —— 它走 CDP，一个进程，还能 `--mobile --size 390,844` 模拟手机（连 `(pointer: coarse)`
> 一起模拟）。

`scripts/smoke.mjs` 还可以单独用来截界面：`--size 1638,1031` 指定窗口尺寸、
`--shot out.png` 出图 —— 改 CSS 时很值得先在**和用户一样的窗口尺寸**下看一遍
（曾经就是因为只在 900px 宽底下看过，联机面板的输入框在宽窗口里横着铺满整个屏幕
还把页面撑出横向滚动条，一直没发现）。

它起的是隔离的无头 Edge（`scripts/smoke.mjs`），探针页把结果 POST 回
`scripts/serve-dist.mjs` 的 `/__probe` 口。（不用 `--dump-dom`：dump 走虚拟时间，
和真实 rAF 主循环对不上，读到的永远是「pending」。）

**规矩：收尾只能杀自己起的那个浏览器实例，绝不能按进程名杀。**
```powershell
Get-Process -Name 'msedge','msedgewebview2' | Stop-Process -Force   # ✗ 千万别这么写
```
这句会把用户自己的浏览器连同 Web UI 一起杀掉，表现就是「web ui 有时闪退」。

`scripts/smoke.mjs` 的做法是：每个实例用独立的 `--user-data-dir`，
收尾时只杀**命令行里带这个专属目录**的进程，并延迟再清一次（无头浏览器会拉一串子进程）。
`--dump-dom` / `--screenshot` 是第二次启动 Edge，用的是另一个 profile 目录，
否则新进程会被已有实例转交掉、直接报错。
实测跑完前后 `msedge` 进程数完全不变。

## 发布

### 一键发布（推荐）

```bash
publish.bat -m "提交说明"
```

按顺序做四件事，任何一步硬失败就停下：

1. **探针当闸门**：先跑 `npm run probe`，不过就不提交（浏览器不可用时加 `--skip-probe`）
2. **提交**：`git add -A` + `git commit`（不带 `-m` 且是双击运行时会问你要说明）
3. **推送**：`origin`（Gitee）+ `github`；某个远端失败只警告，不让后面的步骤停下
4. **构建**：先看 `src-tauri/binaries/` 里有没有 EasyTier，缺了就 `fetch:easytier`；
   如果检测到 `snake-army.exe` 正在运行（它会锁住编译产物，直接编会报
   `拒绝访问 (os error 5)`），会问你要不要关掉它（也可以加 `--kill`）；
   最后 `build:exe` + `pack:release`

```bash
publish.bat -m "..." --skip-probe    跳过探针
publish.bat -m "..." --no-build      只提交推送，不构建
publish.bat --dry-run                只把计划打出来，什么都不改
```

> 逻辑在 `scripts/publish.mjs`，`publish.bat` 只包一层。为什么不全写在 .bat 里：
> cmd 是按**控制台代码页**读批处理文件的，里面写 UTF-8 中文会被读乱、甚至把语法拆坏
> （这个坑踩过，那版 .bat 直接跑不起来）。所以 .bat 保持纯 ASCII，中文提示都在 Node 里。
> 它只按进程名关 `snake-army.exe`（我们自己的桌面版）这一个程序，其它一律不碰。

### 手动发布

### 出一个「完整可运行」的包

```bash
npm run build
```

依次做三件事：下载 EasyTier（还没有的话）→ 编译并打包 exe → 组装便携包。产物：

```
release/snake-army-0.3.0-win-x64.zip      14.5 MB
  snake-army.exe                           3.11 MB   主程序（前端已经嵌进去了）
  binaries/easytier-core.exe              23.27 MB   跨网用
  binaries/easytier-cli.exe                9.51 MB   排查用
  binaries/wintun.dll                      0.41 MB   虚拟网卡驱动
  binaries/Packet.dll                      0.21 MB   WinDivert 用户态 DLL
  binaries/WinDivert64.sys                 0.09 MB   UDP 广播转发要的内核驱动
  README.md
```

解压就能双击跑，不用安装，也不用单独去下 EasyTier。

**`binaries/` 里五个文件一个都不能少。** 少 `Packet.dll` 的话
`easytier-core.exe` 会直接以 `0xC0000135`（STATUS_DLL_NOT_FOUND）退出，
连日志都来不及打。这是实测踩出来的：第一版就漏了，包里的 EasyTier 起不来。

**重新打包前先关掉正在运行的程序。** 链接阶段要写 `snake-army.exe`，
如果还有实例开着，Windows 会锁住它，构建会直接以
`拒绝访问。 (os error 5)` 失败（exit 1）。卡住就先：

```bash
taskkill /IM snake-army.exe /F
```

### 发到 Gitee Releases

仓库在 Gitee，而且这台机器的 hosts 把 github.com 整个指到了 127.0.0.1，所以发行版发 Gitee：

**网页**：仓库 →「发行版」→「新建发行版」，填 tag（比如 `v0.1.0`），
把上面那个 zip 传上去。

**或者 API**：

```bash
curl -X POST "https://gitee.com/api/v5/repos/nxbznine_bilibili/h5-snake-army/releases" \
  -d "access_token=<你的令牌>" \
  -d "tag_name=v0.3.0" \
  -d "name=贪吃蛇 v0.3.0" \
  -d "body=首个可发布版本"

# 拿到 release id 之后传附件：
curl -X POST "https://gitee.com/api/v5/repos/nxbznine_bilibili/h5-snake-army/releases/<id>/attach_files" \
  -d "access_token=<你的令牌>" \
  -F "file=@release/snake-army-0.3.0-win-x64.zip"
```

安装器（NSIS/MSI）这条路**没走**：Tauri 的打包工具要从 GitHub 现场下载，
而本机 hosts 把 github.com 整个指到了 127.0.0.1。便携包解压即用，够用。

### 版本号写在哪

两处要一起改：`package.json` 的 `version`（决定 zip 文件名）和
`src-tauri/tauri.conf.json` 的 `version`（决定程序属性里的版本），
另外前端 `index.html` 里的 `APP_VERSION` 管的是联机握手时的版本校验。

## 联机的已知边界

已验证：

- 局域网房间端到端跑通（两个无头浏览器 + 真实内嵌信令服务）：搜索到房间 → 点加入 →
  双方 `open=true`、`count=2`、`errs=[]`。
- EasyTier 的进程管理跑通（有单元测试）：能找到二进制、按参数拉起、读到日志、停掉。
- 座位表这套信令的单元测试 + 端到端跑通：`cargo test` 里的 `room_metadata_and_seats`
  覆盖「挂 offer → 取座位 → 递 answer → 重复递 409 → 玩家人满给观战席 → 没 offer 的座位 400」；
  `lan-host.py` 用同一套请求序列在本机也跑了一遍（17 项全过），两边行为一致。
- 页面侧的座位逻辑跑通（`npm run probe`）：座位分配 1/2/3/-1、快照一人一份且 `you` 正确、
  中途入座补蛇（2→3 且带出生动画）、按键按座位分发（观战席的按键被丢弃）、
  观战锁死（不发操作、按钮隐藏）。

未验证 / 有前提：

- **在线版（https）上进不了 http 房间**：这是浏览器的混合内容硬限制，不是 bug。
  https 下能用的只有「连接码」；`127.0.0.1` 算可信来源，所以同机开房仍可直连。
- **多客机的真实 WebRTC 没在这台机器上验证过**：需要三台以上的真机（或至少两个浏览器
  实例 + 一台开房机）才能把「一条连接一个座位」真跑起来；本机只能验到座位表这一层。
- **真实的跨网连接没在这台机器上验证过**：EasyTier 建虚拟网卡需要管理员权限，
  而当前账户不是管理员（`is_admin = false`，也没有 wintun 驱动）。
  要真正跑通，需要以管理员身份运行，并且两台机器都在。
- 官方的 `public.easytier.cn` 已失效，得另外找会合点。
- WebRTC 直连只在**本机回环**验证过；真实局域网 / 公网需要两台真机。
- 公共免费 TURN 实测**全部失效**，所以纯 WebRTC 方案在对称 NAT 下打不通。
- 同一个 Wi-Fi 下如果连不上，直接填对方的局域网 IP（面板上的第二个输入框）通常能解决。
